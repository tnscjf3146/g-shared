# 회의 안건 · 공급자 선택 정책

**요청** 김상해 · 2026-09-08 · **필요 시간** 15분 · **참석** 전원

---

## 딱 하나만 정하면 됩니다

> **GPU 작업을 누가, 어떻게 맡게 할 것인가.**

지금 컨트랙트는 **의뢰자 본인만 아니면 아무나 선착순**으로 수락합니다. 이걸 그대로 둘지 바꿀지 정해야 합니다.

**이 결정이 안 나면 에스크로를 SSAFY 체인에 올릴 수 없습니다.**

---

## 왜 지금인가

### 공격이 성립합니다

```
악성 주소가 봇으로 모든 FUNDED 작업을 먼저 수락한다
결과는 제출하지 않는다
의뢰자는 제한 시간이 끝날 때까지 자금을 못 쓴다
```

**SSAFY 체인은 가스가 0 이라 공격 비용이 사실상 없습니다.** 그리고 MVP 는 담보가 0 이라 잠수해도 잃을 게 없습니다. 봇 하나로 서비스를 마비시킬 수 있습니다.

### 임계 경로 맨 앞에 있습니다

```
공급자 선택 정책 결정
  → 컨트랙트 반영
     → 체인 가드 제거
        → SSAFY 체인 배포
           → 백엔드 이벤트 구독 · 프론트 지갑 연동
```

**하루 밀리면 뒤가 전부 하루 밀립니다.** 지금 백엔드와 프론트가 붙을 컨트랙트 주소가 없는 상태입니다.

---

## 선택지 셋

### A. 선착순 그대로

의뢰자 본인만 아니면 누구나 수락합니다. 지금 코드입니다.

| | |
|---|---|
| 공격 차단 | ❌ 안 됨 |
| 기획 정합 | ⭕ 원래 설계 그대로 |
| 중앙 권한 | 없음 |
| 구현 | 0 |

**동한님이 이 상태로는 배포 승인을 거절했습니다.**

### B. 등록된 공급자만 수락 (allowlist)

컨트랙트에 등록 명단을 두고, 명단에 있는 주소만 `acceptJob` 을 부를 수 있게 합니다. 명단은 **누가 일할 자격이 있는지**만 정하고, **어느 작업을 잡을지는 여전히 선착순**입니다.

| | |
|---|---|
| 공격 차단 | 🟡 봇이 등록 절차를 통과해야 하므로 비용이 오름 |
| 기획 정합 | ⭕ 선착순 유지 |
| 중앙 권한 | 🟡 등록·해제 권한이 생김 (자금은 못 건드림) |
| 구현 | 반나절 |

**이형동님이 백엔드에 Worker 등록을 이미 만들어 두었습니다.** 그 명단을 온체인에 반영하는 방식입니다.

### C. 의뢰자가 지명하고, 지명된 공급자가 수락 (동한님 안)

작업을 만들 때 공급자를 지정합니다. 백엔드는 GPU 사양과 예상 시간으로 **추천**하고, 의뢰자가 **선택**합니다. 지명된 공급자만 `acceptJob` 을 부를 수 있습니다.

```solidity
createJob(price, matchedProvider)
acceptJob    require(msg.sender == job.provider)
```

| | |
|---|---|
| 공격 차단 | ⭕ 완전히 막힘 |
| 기획 정합 | 🟡 아래 참고 |
| 중앙 권한 | 없음 (의뢰자가 정함) |
| 구현 | 반나절 |

**기획 정합을 다시 따져 봤습니다.** 처음에는 "중개자가 생긴다" 고 판단했는데 **정확하지 않았습니다.**

- 배정 주체는 **백엔드가 아니라 의뢰자**입니다. 백엔드는 추천만 합니다. "서버는 추천만 한다" 와 어긋나지 않습니다.
- 공급자도 여전히 `acceptJob` 으로 **수락 여부를 직접 결정**합니다. 양쪽 합의가 남습니다.
- 다만 **공급자가 일감 목록에서 자유롭게 골라 잡는 그림**은 사라집니다. 확장 경로로 잡아 뒀던 역경매도 다시 설계해야 합니다.

## 도메인별 영향

| | A · 선착순 | B · allowlist | C · 지명 |
|---|---|---|---|
| **프론트** | 그대로 | 그대로 | 작업 생성 화면에 **공급자 선택 단계 추가** |
| **백엔드** | 그대로 | **등록 명단을 온체인에 반영**하는 기능 | 추천 API 를 작업 생성 흐름에 연결 |
| **시스템·Worker** | 일감 감시 후 선착순 수락 | 등록 후 선착순 수락 | **자기가 지명된 작업만** 감시 |
| **블록체인** | 없음 | 명단 관리 함수 + 권한 | 인자 추가 + 권한 검사 |
| **발표** | "공급자가 직접 잡는다" | 같음 | **"의뢰자가 고른다" 로 문구 수정** |

## 제 권고

**B 를 권합니다.** 이유는 셋입니다.

1. **기획 문구를 안 고쳐도 됩니다.** 발표 시나리오와 특장점이 그대로 갑니다.
2. **다른 도메인 변경이 가장 적습니다.** 프론트와 시스템이 그대로입니다.
3. **이미 있는 것을 씁니다.** 백엔드 Worker 등록이 이미 돌아갑니다.

**다만 B 는 공격을 완전히 막지 못합니다.** 등록만 통과하면 여전히 선점할 수 있습니다. 그래서 **B 를 고르면 등록 절차를 얼마나 빡빡하게 할지**를 함께 정해야 합니다.

**완전한 차단이 우선이면 C 가 맞습니다.** 다만 프론트에 화면이 하나 늘고, 발표 문구를 손봐야 합니다.

**A 는 선택지가 아닙니다.** 배포 승인이 안 납니다.

## 함께 정하면 좋은 것 (같은 자리에서 5분)

**작업마다 실행 제한 시간이 다른가.**

지금은 모든 작업에 똑같은 시간을 줍니다. GPU 작업 시간이 천차만별이라 큰 작업은 항상 만료됩니다.

AI 가 예상 소요 시간을 추정하기로 되어 있으니, **그 값을 작업마다 넣는 방식**이 자연스럽습니다. 다만 의뢰자가 지나치게 짧게 잡지 못하도록 허용 범위가 필요합니다.

**이형동님 의견이 필수입니다.** 추정값의 정확도와 범위를 아는 분이라서 그렇습니다.
