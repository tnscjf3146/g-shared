# 과거 로그를 한 번만 밀어 넣는 방법

상시 수집과 백필은 **성격이 다르다.** 상시 수집은 "계속 자라는 것"을 따라가는 장치이고,
회전본은 더 이상 자라지 않는 과거다. 그 둘을 같은 장치로 다루다가 실패한 기록이
`수집-함정.md` 의 10번이다.

이 문서는 그래서 필요할 때 쓰는 **일회성 절차**다. 상시 설정(`alloy-config.alloy`)은
건드리지 않는다.

---

## 언제 필요한가

| 상황 | 백필이 필요한가 |
| --- | --- |
| 스택이 뜬 뒤의 기록 | **아니다.** 실시간 tail 이 다 잡는다 |
| 백엔드의 과거 | **아니다.** `backend_archive` 가 상시로 읽는다 |
| nginx 의 과거 | **그렇다.** 회전본을 상시 수집하지 않기로 했다 |
| 스택이 꺼져 있던 구간 | 그렇다 |

**먼저 "그 과거가 정말 필요한가"를 묻는다.** nginx 접근 로그의 과거는 대부분 스캐너 소음이다.
9월 18일 사건을 추적할 때 실제로 쓰인 것은 백엔드 압축본이었다.

---

## 왜 상시 수집으로 하면 안 되는가

셋이 동시에 걸린다. 자세한 것은 `수집-함정.md` 10번에 있다.

| | |
| --- | --- |
| 시각 | nginx 블록에 timestamp 스테이지가 없어 과거가 "지금"으로 들어간다 |
| 재적재 | 이 서버의 logrotate 는 `dateext` 없이 숫자를 민다. 회전할 때마다 같은 경로가 다른 내용이 되어 전체를 다시 읽는다 |
| 레벨 | 회전본은 `add_level` 을 타지 않아 회전된 오류에 level 이 안 붙는다 |

백필은 **한 번 돌고 끝나므로** 재적재 문제가 없고, 아래처럼 시각과 레벨을 제대로 붙인다.

---

## 절차

### 1. 별도 설정 파일을 만든다

상시 설정을 고치지 않는다. 백필 전용으로 따로 쓴다.

```bash
cd ~/S15P21E204/infra/observability
cp alloy-config.alloy /tmp/backfill.alloy
```

`/tmp/backfill.alloy` 의 내용을 **아래 넷만** 남기고 지운다.

```alloy
loki.write "default" {
	endpoint {
		url = "http://loki:3100/loki/api/v1/push"
	}
}

local.file_match "nginx_rotated" {
	path_targets = [{
		__path__ = "/var/log/nginx/access.log.*",
		service  = "nginx",
		source   = "backfill",   // 상시 수집과 구분한다
	}]
}

loki.source.file "nginx_rotated" {
	targets    = local.file_match.nginx_rotated.targets
	forward_to = [loki.process.nginx_backfill.receiver]

	decompression {
		enabled       = true
		format        = "gz"
		initial_delay = "10s"
	}
}

loki.process "nginx_backfill" {
	forward_to = [loki.write.default.receiver]

	// **이것이 핵심이다.** 이 스테이지가 없으면 9월 7일 기록이 "지금"으로 들어간다.
	// nginx 기본 포맷의 시각은 대괄호 안에 있다: [07/Sep/2026:00:13:28 +0900]
	stage.regex {
		expression = "\\[(?P<ts>\\d{2}/\\w{3}/\\d{4}:\\d{2}:\\d{2}:\\d{2} [+-]\\d{4})\\]"
	}

	stage.timestamp {
		source = "ts"
		format = "02/Jan/2006:15:04:05 -0700"
	}

	// 서명 URL 을 가린다. 상시 경로의 redact 와 같은 이유다.
	stage.replace {
		expression = "(?i)(?:sig|signature|token|access_token|x-amz-signature)=([^&\s]+)"
		replace    = "REDACTED"
	}
}
```

> `source = "backfill"` 로 두면 나중에 `{source="backfill"}` 로 지우거나 걸러 낼 수 있다.
> 상시 수집분(`file`)과 섞이지 않는다.

> `.gz` 와 평문(`.1`)을 한 컴포넌트에 넣었다. `decompression` 은 확장자를 보고 판단하므로
> 섞여 있어도 된다. 상시 설정에서 둘로 나눴던 것은 다른 이유(경로 패턴)였다.

### 2. 한 번만 돌린다

상시 스택과 **다른 이름**으로 띄운다. `obs-alloy` 를 건드리지 않는다.

```bash
docker run --rm \
  --name obs-backfill \
  --network observability_default \
  -v /tmp/backfill.alloy:/etc/alloy/config.alloy:ro \
  -v /var/log/nginx:/var/log/nginx:ro \
  grafana/alloy:v1.7.5 \
    run --server.http.listen-addr=0.0.0.0:12345 \
        --storage.path=/tmp/alloy-backfill \
        /etc/alloy/config.alloy
```

`--rm` 과 `/tmp` 저장 경로가 중요하다. **위치 기록이 남지 않아야** 다음에 또 읽는 일이 없다.

### 3. 다 들어갔는지 확인하고 멈춘다

다른 터미널에서 센다. 압축 해제에 10초 지연이 있으니 조금 기다린다.

```bash
docker exec obs-grafana wget -qO- --post-data="" http://loki:3100/flush

docker exec obs-grafana wget -qO- \
  'http://loki:3100/loki/api/v1/query?query=sum(count_over_time({source="backfill"}[30d]))'
```

원본과 대조한다. **"돌아간다"를 로그 메시지로 판단하지 않는다.**

```bash
zcat /var/log/nginx/access.log.*.gz | wc -l
cat /var/log/nginx/access.log.[0-9] | wc -l
```

수가 맞으면 `Ctrl+C` 로 멈춘다. `--rm` 이라 컨테이너와 위치 기록이 함께 사라진다.

### 4. 시각이 제대로 붙었는지 본다

**이 확인을 건너뛰면 백필하는 의미가 없다.** Grafana 에서 본다.

```logql
{source="backfill"}
```

시간 범위를 `Last 30 days` 로 두고 **그래프가 날짜에 걸쳐 퍼져 있는지** 본다. 한 자리에
막대 하나로 몰려 있으면 시각 파싱이 실패한 것이다. 그때는 4번 함정과 같은 상태다.

## 되돌리기

`deletion_mode` 를 껐으므로 삭제 API 로는 못 지운다. 잘못 들어갔으면 둘 중 하나다.

| | |
| --- | --- |
| 통째로 다시 | `docker compose -p observability down -v` 후 재기동. 상시 수집분은 원본 파일에서 다시 읽히므로 잃는 것이 없다 |
| 그냥 둔다 | `source="backfill"` 라벨로 갈려 있으므로 평소 질의(`source="file"`, `source="container"`)에는 안 섞인다. 30일 뒤 보존 기간으로 사라진다 |

**대부분은 그냥 두어도 된다.** 라벨을 나눈 이유가 이것이다.
