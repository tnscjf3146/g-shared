# Jira · GitLab → Mattermost 알림 연동 (2026-08-28)

> 스프린트 작업 완료 & MR 알림을 Mattermost 채널로 보내기.
> **핵심: MCP가 아니라 각 서비스의 웹훅/기본 연동으로 한다.** (MCP는 Claude를 띄워놔야 동작해서 24시간 자동 알림엔 부적합)

---

## 0. 큰 그림

| 알림 | 방식 |
|---|---|
| GitLab MR 등록/머지/닫힘 → MM | GitLab **기본 연동** (Mattermost notifications) |
| Jira 스프린트 작업 완료 → MM | Jira **자동화 규칙** + MM Incoming Webhook |

공통 준비물: **Mattermost Incoming Webhook URL** (알림 받을 채널 지정 후 발급)

---

## 1. GitLab MR → Mattermost (기본 연동, 코드 0줄)

`프로젝트 → 설정 → 통합 → Mattermost 알림`

- **트리거 이벤트 선택**: "A merge request is created, merged, closed, or reopened" 체크
- 이벤트 옆 **채널 칸(`my-channel`)** = 메시지 적는 곳이 아니라 **어느 채널로 보낼지 지정하는 칸**
  - 비우면 웹훅 기본 채널로 감 / 채널명 적으면 그 이벤트만 그 채널로
- Webhook URL 붙여넣기 → Test settings → 저장

⚠️ **메시지 문구는 GitLab에 고정, 이 화면에서 못 바꿈.** 바꾸려면 아래 4번(중계) 필요.

---

## 2. Jira 스프린트 작업 완료 → Mattermost (자동화 규칙)

`프로젝트 → 프로젝트 설정 → 자동화 → 규칙 만들기` (한국어 UI 기준)

1. **트리거**: `이슈 전환됨` — 시작: `모든 상태` / 대상: `완료`(팀 완료 상태 이름 그대로)
2. **조건**: `조건 → JQL 조건`
   - `sprint in openSprints()` (진행 중 스프린트 이슈만)
   - 또는 `sprint is not EMPTY` (스프린트에 속하기만 하면)
   - ※ "스프린트 비어있지 않음"이 필드 조건 목록에 잘 안 떠서 **JQL 조건이 제일 확실**
3. **작업**: `작업 → 웹 요청 보내기`
   - URL = MM 웹훅 URL / 메서드 = POST / 콘텐츠 유형 = `application/json`
   - 본문(사용자 지정 데이터):
     ```json
     {"text": "✅ *{{issue.key}}* 완료 — {{issue.summary}}\n담당: {{issue.assignee.displayName}}\n{{issue.url}}"}
     ```
4. 저장 → 규칙 **켜기**

### 알아둘 것
- **"완료" 기준 = 상태(Status) 필드로 감시** (Resolution 필드도 가능하지만 워크플로우 설정 의존이라 Status가 무난)
- 완료 컬럼 상태 이름을 트리거 대상에 정확히 넣어야 함 (Done/완료/Closed 등)
- 하위작업 시끄러우면 조건에 `이슈 유형 ≠ 하위 작업` 추가
- 트리거는 "사람이 완료로 옮기는 순간" 발동. "스프린트 종료"는 별개 이벤트라 안 잡힘

## 3. 봇 이름 · 아이콘 바꾸기

웹훅 본문에 필드 추가:
```json
{
  "username": "스프린트 알리미",
  "icon_emoji": ":white_check_mark:",
  "text": "..."
}
```
(이미지 쓰려면 `icon_emoji` 대신 `"icon_url": "https://.../logo.png"`)

⚠️ **override가 서버에서 꺼져 있으면 위 필드가 전부 무시됨.** 사용자 우회 불가.
- 해결: 관리자가 `시스템 콘솔 → 통합 → 통합 관리`에서
  - `Enable integrations to override usernames` = 참
  - `... override profile picture icons` = 참
- 안 켜주면 → 봇 계정(API 방식, 중계 필요)뿐이라 더 복잡. 그냥 기본 이름으로 쓰는 게 현실적.

## 4. 메시지 문구를 완전히 커스텀하려면 (GitLab)

기본 연동은 문구 고정 → 자유 편집하려면 중계를 끼움:
```
GitLab Webhook → (중계 스크립트/서버) → Mattermost Incoming Webhook
```
- GitLab `설정 → 웹훅`에서 이벤트 JSON을 중계 URL로 전송
- 중계가 원하는 형식으로 가공 후 MM 웹훅으로 재전송
- 단점: 상시 돌릴 서버가 하나 필요 → 정말 필요할 때만.

---

## 5. 연결 확인 방법

**웹훅 테스트 (터미널):**
```bash
curl -i -X POST -H 'Content-Type: application/json' \
  -d '{"text":"🔔 연결 테스트"}' \
  https://<mm주소>/hooks/웹훅키
```
- 채널에 뜨면 정상 / `200`인데 안 뜸 = 다른 채널 / `403·404` = URL·비활성 / `disabled` = 관리자가 꺼둠

**Jira 규칙 테스트:** 규칙 상세 → **감사 로그(Audit log)**에서 성공/실패 확인. 없으면 이슈를 실제로 완료로 옮겨 테스트.

**GitLab 테스트:** 통합 설정의 **Test settings** 버튼.

## 요약

- MCP 아님 → 웹훅/기본 연동으로 해결
- GitLab MR = 기본 연동 체크 몇 개 / Jira 완료 = 자동화 규칙 + JQL 조건 + 웹 요청
- 문구 커스텀은 GitLab 기본 연동에선 불가, 이름·아이콘은 override 켜져 있을 때만
- 막히면 웹훅 curl 테스트 + Jira 감사 로그부터 확인
