> 2026-08-27 · 학습 커리큘럼 체크리스트

## 시작하기 전에

블록체인 = 기존 기술 3개의 조합.

| 재료 | 역할 |
|---|---|
| 암호학 | 해시로 과거를 고정, 서명으로 소유를 증명 |
| 분산 시스템 | 여러 노드가 순서에 합의 |
| 경제적 인센티브 | 정직하면 보상, 속이면 손해 |

**흔한 실패 경로**: Solidity 문법 → 토이 프로젝트 → "그래서 이게 왜 필요한데?"에서 멈춤
**권장 경로**: Phase 0~3 (원리) → Phase 7 (실습) → 나머지

### 목적별 최소 경로

| 목적 | Phase |
|---|---|
| 개념 이해 (기획·면접) | 0 · 1 · 2 · 3 · 11 |
| 컨트랙트 개발자 | 0~3 → 6 · 7 · 8 (깊게) → 10 |
| 코어·인프라 개발 | 1~4 (깊게) → 5 · 9 |

## Phase 0 · 왜 블록체인인가

**목표**: 기술이 아니라 **문제**를 먼저 이해한다.

- [ ] 이중지불(double spending)이 왜 디지털에서만 생기는지 설명
- [ ] 은행(중앙 신뢰 기관)이 실제로 해주는 일 3가지 — 신원 확인 · 잔액 검증 · 순서 결정
- [ ] 비잔틴 장군 문제를 비유 없이 설명
- [ ] "trustless" = 아무도 안 믿는다 ✗ / 코드와 인센티브를 믿는다 ✓
- [ ] 블록체인이 푸는 문제는 **저장이 아니라 합의**
- [ ] 느리고 비싼데 왜 쓰는가 — 그 대가로 얻는 것
- [ ] 퍼블릭 / 프라이빗 / 컨소시엄 체인 차이. 프라이빗이 왜 종종 무의미한가

> **핵심 질문**: DB 다중 복제와 블록체인은 뭐가 다른가?
> → 복제는 서버들이 서로를 **신뢰**한다. 블록체인은 참여자가 서로를 **속이려 한다고 가정**한다.

## Phase 1 · 암호학 ★

**목표**: 블록체인의 90%인 **해시**와 **전자서명**을 확실히 잡는다.

### 해시

- [ ] 3가지 성질 — 단방향 · 충돌 저항 · 눈사태 효과
- [ ] 입력 1비트 변경 → 출력 변화를 **직접 실행**해서 확인
- [ ] 해시는 암호화가 **아니다** (복호화 개념 자체가 없음)
- [ ] 해시 포인터 — 이것만으로 왜 위조가 탐지되는가

### 전자서명

- [ ] 대칭키 / 비대칭키 차이
- [ ] 개인키 → 공개키는 되는데 역방향은 왜 불가능한가 (타원곡선, 개념 수준)
- [ ] 서명이 보장하는 3가지 — 인증 · 무결성 · 부인방지
- [ ] **서명은 개인키로, 검증은 공개키로.** 방향 절대 안 헷갈림
- [ ] 지갑 주소 = 공개키의 해시. 왜 공개키를 바로 안 쓰나
- [ ] "지갑에 코인이 들어있다"가 틀린 표현인 이유 (지갑엔 키만 있다)
- [ ] 니모닉 12/24 단어 → 무한한 키 (BIP-32/39/44)
- [ ] 개인키 분실 = 복구 **원리적으로 불가능**한 이유

### 머클 트리

- [ ] 구조를 직접 그릴 수 있다
- [ ] 루트 해시 하나로 수천 거래를 검증하는 원리
- [ ] 머클 증명이 `log n` 크기인 이유
- [ ] 이 덕분에 라이트 클라이언트가 가능한 이유

> **실습**: Python `hashlib`로 해시 체인 10칸. 중간 블록을 고치면 뒤가 전부 깨지는 걸 눈으로 확인. 40줄.

## Phase 2 · 블록과 체인

**목표**: 블록체인이 결국 **해시 포인터 연결 리스트**임을 안다.

- [ ] 블록 헤더 필드 — 이전 해시 · 머클 루트 · 타임스탬프 · 난이도 · 논스
- [ ] 과거 블록 수정이 불가능한 이유 — 이후 전부 재계산
- [ ] append-only 구조의 이유와 대가
- [ ] UTXO 모델 (비트코인) — 잔액이 아니라 "안 쓴 출력"의 집합
- [ ] 계정/잔액 모델 (이더리움)
- [ ] 두 모델의 트레이드오프 — 병렬성·프라이버시 vs 단순함
- [ ] 블록체인 = **상태 전이 함수의 로그**
- [ ] 제네시스 블록이 특별한 이유

## Phase 3 · 합의 ★

**목표**: 서로 못 믿는 노드들이 **순서에 동의**하는 방법을 이해한다.
→ [26_08_27_라이브러리.md](26_08_27_라이브러리.md)의 분산 시스템 내용(CAP, 최종 일관성)과 직결.

### 기초

- [ ] CAP 정리 — 블록체인은 무엇을 택했나 (가용성 + 분할내성, 일관성은 최종적)
- [ ] 합의 = 분산 환경에서 **순서를 정하는 문제**
- [ ] 비잔틴 내성이 단순 장애 내성보다 훨씬 어려운 이유
- [ ] 시빌 공격 — 신원이 공짜면 투표가 무의미
- [ ] 비잔틴 결과: 배신자 f명 견디려면 3f+1명 필요 (악의 < 1/3)
- [ ] 무엇을 세나 — PoW=해시파워, PoS=지분, PBFT=검증 노드 수. 안전 임계 BFT계 1/3 · PoW 1/2
- [ ] 합의 알고리즘의 본질 = **신원에 비용을 붙이는 것** (PoW=연산, PoS=자본)

### 작업증명 PoW

- [ ] 논스 바꿔가며 목표값 이하 해시 찾기 — **직접 구현**
- [ ] 난이도 조절이 필요한 이유와 방식
- [ ] 채굴은 추측 게임, 검증은 즉시 — 이 비대칭이 핵심
- [ ] 가장 긴 체인 규칙, 포크가 자연 해소되는 원리
- [ ] 51% 공격으로 **할 수 있는 것** (거래 되돌리기) / **없는 것** (남의 코인 훔치기)
- [ ] 확정성이 확률적인 이유, 왜 "6블록 대기"인가
- [ ] 에너지 소비 = 버그가 아니라 보안 예산이라는 논리 + 반론

### 지분증명 PoS

- [ ] 스테이킹 · 검증자 · 슬래싱
- [ ] PoW의 에너지를 무엇으로 대체했나
- [ ] Nothing-at-stake 문제와 해결
- [ ] PoS에서 명시적 확정성이 생기는 이유
- [ ] 비판점 — 부의 집중, 유동성 스테이킹 재중앙화

### 그 외

- [ ] 고전 BFT (PBFT, Tendermint) vs 나카모토 합의
- [ ] 고전 BFT가 노드 수를 못 늘리는 이유 — O(n²) 메시지
- [ ] 소프트 포크 / 하드 포크
- [ ] MEV가 무엇이고 왜 생기나

## Phase 8 · 보안

> 컨트랙트 버그는 **패치 불가 + 돈이 바로 사라진다.** 웹 개발과 위험 차원이 다르다.

### 핵심 공격

- [ ] **재진입(Reentrancy)** — 취약 코드 직접 작성해서 털어보기
- [ ] Checks-Effects-Interactions 패턴 / 외부 호출은 **항상 마지막**
- [ ] 접근 제어 누락 (`onlyOwner` 빠뜨림)
- [ ] `tx.origin`을 인증에 쓰면 안 되는 이유
- [ ] 오버플로 — 0.8 이후 기본 방어, `unchecked` 주의
- [ ] 블록 해시·타임스탬프를 난수로 쓰면 안 되는 이유
- [ ] 가격 오라클 조작 — 스팟 가격 금지, TWAP
- [ ] 플래시 론 공격
- [ ] 프론트러닝 · 샌드위치 — 멤풀이 공개라는 사실의 함의
- [ ] DoS — 배열 순회 가스 초과, 인출 실패로 잠김
- [ ] Push vs Pull — 송금은 사용자가 직접 인출하게
- [ ] `delegatecall` 위험, 프록시 스토리지 충돌
- [ ] 업그레이드 가능 = 탈중앙화 훼손이라는 트레이드오프

### 도구·사례

- [ ] Slither 정적 분석 실행
- [ ] 해킹 사례 3건을 원인 수준까지 — The DAO · Parity · Ronin

> **실습**: [Ethernaut](https://ethernaut.openzeppelin.com/) 10문제 이상. 보안이 머리에서 손으로 내려온다.

## Phase 11 · 한계와 비판 ★

> **못 쓰는 곳을 아는 것**이 쓸 곳을 아는 것보다 중요하다.
> 여기를 통과 못 하면 기술이 아니라 신념을 배운 것이다.

- [ ] "올리면 위조 불가"는 **입력의 진실성은 보장 안 한다** — garbage in, immutable garbage
- [ ] 개인정보 온체인 = GDPR 삭제권과 원리적 충돌
- [ ] "기업 블록체인" 대부분이 DB로 충분했다는 비판
- [ ] 부적합한 경우 5개 이상
- [ ] 정말 필요한 조건 3가지 — 상호 불신 · 중앙 관리자 불가 · 순서와 불변성이 가치의 핵심
- [ ] 확장성 · 비용 · UX · 규제의 현실적 한계
- [ ] 인프라(RPC, 스테이킹 서비스)로의 **재중앙화** 비판
- [ ] 투기와 기술을 분리해서 말할 수 있다

### 블록체인이 필요한가 — 4단계 판별

```
1. 여러 주체가 같은 데이터를 쓰는가?        아니오 → DB
2. 그 주체들이 서로를 못 믿는가?            아니오 → 공유 DB
3. 모두가 인정할 중앙 관리자가 없는가?       있음   → 관리자 + DB + 감사 로그
4. 성능·비용 저하를 감당할 수 있는가?        아니오 → DB
                                             예     → 블록체인 검토
```

대부분 1~3에서 걸러진다. 그걸 아는 게 전문성이다.
