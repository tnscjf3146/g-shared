## 1. AI 추론(Inference)과 분산

- **추론(inference)** = 이미 학습이 끝난 모델을 실제로 사용하는 단계. 학습된 모델에 새 입력을 넣어 결과를 뽑는 것.
  - 학습(training) = 데이터로 모델 파라미터를 만드는 과정 / 추론 = 그 완성된 모델을 쓰는 과정.
  - 비유: 학습 = 요리사가 레시피 배우기, 추론 = 배운 레시피로 실제 요리하기.
- **분산 추론(distributed inference)** = 추론을 여러 GPU/서버에 나눠 실행.
  - 이유 ① 모델이 너무 커서 GPU 한 장에 안 들어감 → 쪼개서 여러 GPU에.
  - 이유 ② 요청이 너무 많아서 한 서버로 감당 안 됨 → 복제 후 분산.
- **추론에 GPU를 쓰나?** → 대부분 씀(행렬곱 병렬연산에 GPU가 압도적). 단 필수는 아님:
  - 작은 모델·속도 안 중요 → CPU 가능.
  - 전용 칩(TPU, NPU, AWS Inferentia)도 사용.
  - 학습은 거의 무조건 고성능 GPU, 추론은 연산량이 적어 더 저렴한 칩으로도 가능.

> ⚠️ 프로젝트 내 "추론" 두 가지 의미 구분 필요:
> ① AI 예측(스케줄링) — 어떤 GPU가 적합한지 예측 (워커 단계, 중앙 조율)
> ② AI 워크로드 실행(inference) — 실제 모델 돌리기 (공급자 GPU, 워커 이후 P2P)

## 2. 도커 허브 / 도커 이미지 (RunPod·Gcube 대비 차별점)

- **도커 이미지** = 프로그램 실행에 필요한 모든 것(코드·모델·라이브러리·설정)을 담은 "택배 상자". 어느 컴퓨터에서든 똑같이 실행됨.
- **컨테이너** = 그 이미지를 실제로 돌리는 상태. (이미지 = 붕어빵 틀, 컨테이너 = 구워진 붕어빵)
- **도커 허브** = 이미지를 올려두고 받아가는 공용 창고. (경쟁 후보: AWS ECR)
- **"템플릿은 도커 이미지로"** = AI 모델을 미리 실행 가능한 이미지로 포장 → 사용자는 모델만 선택, 컨테이너 설정 불필요.
- **"도커 허브로 한다"** = 그 이미지들을 도커 허브에 올려두고 공급자가 받아 실행.
- (미결) 저장소 Docker Hub vs AWS ECR / 공급자 설치프로그램에 이미지 포함 여부.

## 3. P2P 흐름

- **P2P (Peer-to-Peer)** = 중앙 서버를 안 거치고 참가자 컴퓨터(노드)끼리 직접 주고받는 방식.
  - 일반: 내 메시지 → 카카오 서버 → 상대. / P2P: 내 컴퓨터 → 상대 컴퓨터 직접.
- **이 프로젝트의 P2P 범위** (회의에서 축소·재정의됨):
  - 학습은 GPU 한 대가 통째로 → P2P 대상 아님.
  - P2P는 ① 결과 파일(LoRA 등) 주고받기 ② 분산 추론에만 사용.
- **3주체 구조**: 사용자 → 워커(적정 GPU 선정) → 공급자(실행) → 결과는 공급자가 사용자에게 직접.
- **서로 어떻게 찾나**: 게시판(레지스트리)에 각자 주소를 블록체인에 올려둠 → 그 주소 보고 IP로 직접 통신. (벼룩시장 게시판 = 연락처만, 거래는 직접)
- **우리 방향**: AI가 추론해서 분산(워커 단계)까지만 조율 → 워커 이후 전부 P2P → 탈중앙.

## 4. Gcube (경쟁 서비스) 3축 비교

데이터얼라이언스 + 네이버클라우드가 운영하는 GPU 공유 플랫폼(gcube.ai).

| 축 | Gcube | 우리 |
|---|---|---|
| 신뢰 구조 | 회사 운영, 블록체인은 정산 투명성 보조 | **블록체인이 판정·에스크로·검증 직접 집행 (중개자 없음)** |
| 설정 자동화 | 이미 함 (에이전트 설치만) | 함 (← **차별점 아님**) |
| GPU 매칭 | 추천 + 상담 혼합, 3계층(Tier1 클라우드/Tier2 전용서버/Tier3 개인) | AI 자동 매칭 (유사) |

- **핵심**: "설정 대신 해주기"는 RunPod엔 통했지만 Gcube엔 안 통함 → 차별점 아님.
- **진짜 차별점**: 중개 회사 없이, 서로 모르는 사람끼리, **블록체인이 정직성을 강제로 보증(trustless)**. Gcube는 네이버클라우드를 믿어야 하지만 우리는 아무도 안 믿어도 됨.

## 5. 블록체인 vs 에스크로 (헷갈렸던 것)

- **에스크로** = "제3자가 돈을 맡아뒀다가 조건 충족 시 준다"는 방식/역할 이름.
- **블록체인(스마트 컨트랙트)** = 그 제3자 역할을 "누가 하느냐"의 답 중 하나.
- 기존 에스크로(네이버페이·법무사)는 그 회사를 믿어야 함(파산·약관변경 리스크). 스마트 컨트랙트는 배포 후 아무도(만든 사람도) 못 바꿈.
- 우리 프로젝트가 에스크로를 회사(백엔드 서버)가 하면 = 우리가 네이버페이가 됨 → "중개 없이"가 거짓말.
- 그래서 미결 **결정1(돈 위치)**: 금융망 보관(회사 방식) vs 온체인 정산(코드 방식). 문서는 온체인 권고.
