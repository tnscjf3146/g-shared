## 2) 빌드 시 환경 변수 상세

루트 `.env` 파일을 `.env.example` 기준으로 생성한다 (docker-compose가 참조).

| 변수 | 용도 | 예시/비고 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | MySQL root 비밀번호 | 임의 지정(최초 기동 시 이 값으로 초기화됨) |
| `MYSQL_DATABASE` | DB 스키마명 | `gshared` |
| `MYSQL_USER` / `MYSQL_PASSWORD` | 앱 접속 계정 | `gshared` / 임의 지정 |
| `MYSQL_HOST` / `MYSQL_PORT` | DB 호스트/포트 | compose 내부: `mysql` / `3306` |
| `REDIS_HOST` / `REDIS_PORT` | Redis | compose 내부: `redis` / `6379` |
| `JWT_SECRET` | JWT 서명 키 | **256bit 이상 랜덤** |
| `CORS_ALLOWED_ORIGINS` | 허용 오리진 | 예: `https://j15e204.p.ssafy.io` |
| `WALLET_AUTH_DOMAIN` / `WALLET_AUTH_URI` / `WALLET_AUTH_CHAIN_ID` | 지갑 서명 로그인 도메인/URI/체인ID | chainId `31221` |
| `STORAGE_PUBLIC_BASE_URL` | 파일 공개 URL 베이스 | 예: `https://j15e204.p.ssafy.io/api/storage` |
| `STORAGE_SIGNING_SECRET` | 서명 URL 시크릿 | 임의 랜덤(비우면 JWT_SECRET 겸용) |
| `ESCROW_CONTRACT_ADDRESS` | 에스크로 컨트랙트 주소 | `0x66178DF08F5938d2ABC17496b6A98F7d776D3c56` |
| `ESCROW_RPC_URL` | 체인 RPC | `https://rpc.ssafy-blockchain.com` |
| `ESCROW_VERIFICATION_REQUIRED` | 결과 검증 필수 여부 | `true`/`false` |
| `ESCROW_KEEPER_PRIVATE_KEY` | 정산 키퍼 개인키 | **비밀 관리 필수** |

- **Frontend** (`frontend/.env`, 커밋 제외): `NEXT_PUBLIC_API_MOCKING`(MSW on/off) 등. 실제 배포 시 목업 OFF.
- **Blockchain** (`blockchain/.env`): `SSAFY_RPC_URL`, `SSAFY_CHAIN_ID`(31221), `SSAFY_PRIVATE_KEY`(배포 지갑).
- **Worker** (`system/worker/worker-config.example.json`): 서버 WS 주소, 지갑 정보 등.

## 3) 빌드 및 배포 절차

### (A) 통합 배포 — docker-compose (권장)
```bash
# 1. 환경변수 준비
cp .env.example .env          # 값 채우기

# 2. 빌드 + 기동 (backend/frontend/ai 각 Dockerfile로 빌드)
docker compose up -d --build

# 3. 상태 확인
docker compose ps
docker compose logs -f backend
```
- 서비스 구성: `backend`(8080), `frontend`(3000), `ai`(내부 8000), `mysql:8`(3306), `redis:8`. 모두 `127.0.0.1`에만 바인딩되고 외부 노출은 Nginx가 담당.
- Flyway가 backend 기동 시 `db/migration`(V1~V24)을 자동 적용.

### (B) 개별 빌드 (로컬/디버깅)
```bash
# Backend
cd back && ./gradlew clean bootJar
java -jar build/libs/app.jar --spring.profiles.active=local

# Frontend
cd frontend && pnpm install && pnpm build && pnpm start

# AI
cd ai && pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000

# Blockchain 배포 (SSAFY 체인)
cd blockchain && pnpm install
# scripts/의 deploy(ssafy) 실행 → 컨트랙트 주소를 .env에 반영
```

### (C) Nginx / TLS
- `infra/nginx/default` 를 서버 `/etc/nginx/sites-available/`에 반영 후 심볼릭 링크.
- 라우팅: `443 → /api → 8080`, `/ → 3000`, `/ws/ → 8080`(WebSocket 업그레이드), `/grafana/ → 3001`.
- `/api/storage`: 본문 5G, 타임아웃 3600s (대용량 데이터셋 업로드용).
- Certbot으로 인증서 발급/갱신. 80 포트는 443으로 리다이렉트.

## 4) 배포 시 특이사항

- **CI/CD 파이프라인 없음(확정)**: Jenkins/GitLab CI 미사용. EC2 에서 `git pull` 후 `docker compose up -d --build` 수동 배포가 공식 절차다.
- **포트 바인딩**: 모든 앱 컨테이너는 `127.0.0.1`에만 바인딩. 외부 접근은 반드시 Nginx(443) 경유.
- **블록체인 선행 배포 필요**: 앱 기동 전 컨트랙트(GCoin, GPUJobEscrow)가 SSAFY 체인에 배포되어 있어야 하며, 주소를 `.env`에 반영. (현재 배포본: `blockchain/deployments/ssafy-31221/deployment.json`)
- **키퍼 개인키**(`ESCROW_KEEPER_PRIVATE_KEY`)는 정산 트랜잭션 서명에 사용 — 절대 커밋 금지, 서버 환경변수로만 주입.
- **DB ddl-auto=validate**: 스키마 변경은 반드시 Flyway 마이그레이션으로. 엔티티만 바꾸면 기동 실패.
- **Worker exe**: `system/worker/packaging/build.ps1`(Windows/PowerShell)로 빌드 → `G-shared.exe`를 저장소 `system/G-shared/`에 갱신 커밋해야 frontend 이미지 빌드 시 다운로드에 반영.
- **타임존**: 컨테이너 `Asia/Seoul` 고정. 체인 기록 시각과 DB 시각 정합성 주의.
