# 4. 시연 시나리오

> 시연 순서에 따른 화면별 · 실행별(클릭 위치 포함) 상세 설명.
> 서비스: **G-shared** — 유휴 GPU 공유 AI 연산 플랫폼.
> 화면 경로·상태 표시 위치는 소스 코드와 대조 확인됨. 버튼 문구는 시연 리허설에서 최종 대조 권장.

## 사전 준비 (시연 전 세팅)
1. 서버 배포 상태 확인 (`https://j15e204.p.ssafy.io` 접속 가능, `docker compose ps` 정상).
2. **MetaMask** 2개 계정 준비: ① 수요자(사용자) ② 공급자. 둘 다 SSAFY 체인(RPC `https://rpc.ssafy-blockchain.com`, ChainID 31221) 추가 + GSC 토큰 임포트.
3. 공급자 PC(또는 데모용 노드)에 `G-shared.exe` 다운로드 준비.
4. 데모용 데이터셋 파일(텍스트 파인튜닝용) 준비.
5. (선택) 온체인 확인용 블록 익스플로러 탭 열어두기.

---

## 시연 흐름 (전체 순서)
```
랜딩 → 회원가입/로그인(지갑연결) →
[공급자] 워커 등록 → G-shared.exe 실행 → ONLINE 대기
[수요자] 작업 생성(워크로드/모델/데이터셋) → GPU 추천·견적 → 에스크로 예치 →
        업로드 → 학습 진행(실시간) → 결과·온체인 검증 → 정산
```

---

## STEP 1. 랜딩 페이지
- **화면**: `/` (marketing, 3D 연출) — `frontend/src/app/(marketing)/`
- **설명**: 유휴 GPU 문제 제기 → 서비스 소개. 3D 인터랙션으로 첫인상 각인.
- **클릭**: 우상단 **[로그인/시작하기]** 버튼 → 인증 화면 이동.

## STEP 2. 회원가입 · 로그인 (지갑 인증)
- **화면**: `/login`, `/signup` — `(auth)/`
- **실행**:
  1. **[회원가입]** 클릭 → 지갑 연결 팝업(MetaMask) → **[서명]** 승인.
  2. EIP-191 서명으로 지갑 주소 인증 → 계정 생성/로그인 완료.
- **포인트**: 소셜 로그인 없이 지갑 서명만으로 인증된다는 점 강조.

## STEP 3. (공급자) GPU 워커 등록
- **화면**: `/workers` → **[워커 등록]** → `/workers/new`
- **실행**:
  1. 공급자 계정으로 로그인 → 워커 등록 화면.
  2. `G-shared.exe` **다운로드**(`/downloads/G-shared.exe`) 후 공급자 PC에서 실행.
  3. 실행 파일이 Windows/NVIDIA 드라이버/도커·WSL 환경을 점검·자동 구성하고 **벤치마크** 수행.
  4. 등록 완료 → 워커가 **ONLINE** 상태로 대기.
- **포인트**: "실행 파일 하나로 등록" + 실측 벤치마크 점수 표시.
- 상태 표시 위치: **워커 카드 하단 표의 마지막 '상태' 칸**(현재 작업 옆) — '작업 가능'(초록)/'권한 필요'(빨강)/'작업 중' 등. 카드 상단 배지의 ONLINE 은 연결 상태일 뿐, 작업 가능 여부는 이 칸이 정본.

## STEP 4. (수요자) 작업 생성
- **화면**: `/jobs` → **[새 작업]** → `/jobs/new`
- **실행 (단계별 위저드)**:
  1. **워크로드 선택**: 텍스트 파인튜닝 선택 (승인된 Docker Image 기반, 컨테이너 설정 불필요).
  2. **모델 · 학습 수준**: 베이스 모델 선택 + 간단/표준/정밀 중 선택 (또는 CUSTOM). 기존 LoRA 어댑터 이어 학습 옵션.
  3. **데이터셋**: 파일 선택 → **브라우저에서 로컬 분석**(샘플 수·토큰 수 등 메타데이터만 추출, 원본은 아직 서버 미전송).
- **포인트**: "데이터 원본 업로드 전에 견적부터" 를 강조.

## STEP 5. GPU 추천 · 예상 비용
- **화면**: 작업 생성 위저드 내 추천 단계
- **실행**:
  1. AI Scheduler가 메타데이터 + 벤치마크 + 학습설정을 XGBoost에 입력 → GPU별 예상 실행시간·비용 순위 제시.
  2. 사용자가 GPU/견적 확인.
- **포인트**: 실측 벤치마크 기반 추천 + 작업 전 확정 견적.

## STEP 6. 에스크로 예치 (온체인)
- **화면**: `/jobs/[jobId]` 또는 예치 단계 / `/wallet`(잔액 확인)
- **실행**:
  1. **[예치/승인]** 클릭 → MetaMask에서 GSC **토큰 approve** 서명.
  2. 이어서 GPUJobEscrow 컨트랙트로 **예치(deposit)** 트랜잭션 서명.
  3. 예치 완료 후에야 데이터셋 **원본 업로드** 시작(서버가 업로드 Hash 대조).
- **포인트**: 컨트랙트 주소엔 개인키가 없어 "회사도 못 꺼낸다". `/jobs/[jobId]/chain` 온체인 패널에서 트랜잭션 확인.

## STEP 7. 학습 진행 (실시간)
- **화면**: `/jobs/[jobId]` (실시간, `use-job-realtime.ts` / WebSocket `/ws/`)
- **실행**: 매칭된 워커의 격리 컨테이너에서 학습 수행. 진행 상태·Loss 차트 등 실시간 표시.
- **포인트**: `lossChart.tsx`, 진행률 실시간 갱신.

## STEP 8. 결과 · 온체인 검증
- **화면**: `/jobs/[jobId]` 결과 탭 + `/jobs/[jobId]/chain`
- **실행**:
  1. 학습 완료 → 결과물(LoRA 어댑터·메트릭) 전달.
  2. 결과 Hash가 블록체인에 기록 → **검증 패널**(`trainingResultVerificationPanel.tsx`, `loraWeightHeatmap.tsx`)에서 무결성 확인.
- **포인트**: 결과 Hash 온체인 대조 = "전달 과정 변조 없음" 증명.

## STEP 9. 정산
- **화면**: `/jobs/[jobId]` / `/wallet`
- **실행**:
  1. 공급자가 결과 해시를 제출(`submitResult`)하면 **컨트랙트가 즉시 공급자에게 예치금 전액을 지급**한다 (별도 사용자 승인 단계 없음).
  2. 사용자는 작업 상태(COMPLETED)와 `/wallet` 잔액 변동, `/chain` 패널·익스플로러에서 정산 트랜잭션을 확인한다.
- **포인트**: 결과 제출 = 정산 — 해시가 온체인 기록과 일치해야 하므로 결과물 바꿔치기가 불가능한 구조.

---

## 마무리 어필 포인트 (컨설턴트 조언 반영)
- **블록체인 익스플로러**로 실제 트랜잭션이 체인에 쌓이는 것을 시연 중 직접 보여줄 것.
- 블록체인 설명은 짧게: "이런 특성이라 신뢰도가 높다 → 실제 이 트랜잭션으로 정산한다" 흐름.
